- Slogan「让事业，多一种可能。」排在同一行；进入首页时逐字呈现打字机动画。
- 主按钮文案改为「创建我的光域空间」。
- 「个人 OPC 经营管理工具」视觉居中，并增加圆角矩形强调色背景。
- 介绍文案改为「OPC 人+Agent协同办公新可能，让事业与成长井井有条。」

**参考**：用户提供的首页截图及透明底 Logo 图片。

### R02：登录页

**目标**：让登录页沿用首页品牌，并统一创建空间的表达。

- Logo 与 R01 相同，使用上述透明底 Logo。
- Slogan「让事业，多一种可能。」在进入登录页时逐字呈现打字机动画。
- 标题「创建你的经营簿」改为「创建你的光域空间」。
- 介绍文案改为「客户、项目、任务与收入，一套工具清晰管理，让事业与成长井井有条」。

**参考**：用户提供的登录页截图。

**当前页面对应**：登录与注册共用 `AuthPanel`，分别由 `/login`、`/register` 承载。Logo 与 Slogan 在两种模式共用；「创建你的经营簿」当前位于注册模式，应在该位置更新为「创建你的光域空间」。登录模式的「欢迎回来」保持现有登录语义。本条仅调整已明确的品牌文案和展示，不改变认证流程。

### R07：客户与合作方共用列表页并支持标签切换

**目标**：在同一页面内快速切换客户与合作方，并用中文表达跟进字段。

- 客户和合作方列表放在同一个页面，通过「客户」「合作方」两个 Tab 切换。
- 按截图展示客户或合作方名称、状态、最近沟通、下一次跟进、关联项目、创建时间；页面字段名继续沿用当前版本。
- 页面参考结构：标题、搜索框、新增按钮、状态筛选、查看已删除选项；列表展示名称、状态、最近沟通、下一次跟进、关联项目、创建时间；底部展示记录数、分页和每页条数。
- 客户与合作方列表均参照用户提供的对应页面截图。

**当前代码对照**：客户、合作方目前分别作为独立导航视图，列表使用通用字段配置。当前客户列表包含编号、行业和累计到账，合作方列表包含编号、行业；目标字段列集与当前列集不同。当前数据层已计算最近沟通、下一次跟进及关联项目，页面需按目标显示对应摘要。

**复检结论**：「下一次跟进」取关联未完成任务的计划日期；计划日期为空时显示空值，不使用截止日期。列表表头支持排序，默认每页 50 条并可选 20、50、100 条；当前 Next.js 页面需从工具栏排序改为列头排序并提供每页选择。

**参考**：用户提供的客户、合作方列表页面截图。

### R08：新增客户抽屉

**目标**：将新增客户表单整理为清晰的单列抽屉，并让资料链接可以逐条维护。

- 表单采用单列布局，参考图中包含：必填客户名称、行业 / 业务领域、客户状态、客户来源、需求说明、备注、资料链接。
- 「资料链接」区域支持新增多条链接；每条包含资料名称和链接地址（可填写 Obsidian、文件路径或网页），并可单独删除。
- 抽屉底部固定显示「取消」「保存」操作。
- 与当前表单对照：当前资料链接以多行文本方式填写（标签与网址 / 路径放在同一行），参考方案改为逐条结构化输入。

**字段兼容规则**：现有「关联项目」字段及数据继续保留，不改字段名；它不进入截图对应的主表单顺序，放在次级信息区域供新增 / 编辑时维护。抽屉宽度按 R05 执行。

**参考**：用户提供的新增客户抽屉截图，重点为资料链接区域。

### R09：客户详情抽屉

**目标**：以清晰的详情字段和关联记录呈现客户经营信息，并提供常用操作。

- 顶部操作包括：编辑、添加任务、添加沟通、添加资料、删除、复制。
- 任务操作入口使用文案「添加任务」。
- 详情主体按纵向字段表呈现，包括：记录 ID、记录版本、客户状态、行业 / 业务领域、客户来源、需求说明、累计到账、当前应收、最近沟通、下一次跟进、关联项目、关联订单、备注、创建时间、更新时间。
- 资料链接区显示资料名称及链接入口。
- 继续呈现关联任务与沟通记录等关联内容。

**当前代码对照**：客户详情当前以双列字段展示，操作入口以编辑、删除为主；沟通记录与资料链接已有相应呈现逻辑，需对照目标图调整布局与入口。

**Demo 对照补充**：demo 的复制按钮将当前记录 ID 复制到剪贴板并提示成功；当前 Next.js 详情没有该入口。Next.js 记录同时有内部 ID 与业务编号，复制和详情显示应使用用户可见的业务编号，不复制内部数据库 ID。目标详情还展示该客户的关联任务、沟通记录，并提供添加任务、沟通和资料的快捷操作；当前页面只提供沟通记录追加表单，缺少关联任务列表和顶部快捷操作。

**复检结论**：客户新增和编辑表单不提供「关联项目」字段或次级信息区。项目新增和编辑表单负责维护关联客户；客户列表的「关联项目」数量从项目关系汇总显示。抽屉宽度按 R05 执行。

**参考**：用户提供的客户详情截图。

- 列表列为：订单名称、客户、交付状态、订单金额、已收、应收、交付日期；参照图中不展示记录编号和操作列。

- 资料链接采用可逐条新增的结构化输入，可填写资料名称和链接地址，并支持删除单条链接；与客户、合作方新增表单保持一致。

#### 订单详情抽屉

- 顶部提供收入流水标题、搜索、新增收入流水、查看已删除等入口。

#### 新增收入流水抽屉

### 功能差异的根本原因

1. 当前前端以 `ENTITIES` 配置驱动通用列表、`RecordForm` 和 `RecordDrawer`，适合快速覆盖增删改查，但把每个业务模块的内容页签、列配置、表单顺序、详情分区和快捷操作压成同一套结构。
2. 数据层并非所有能力都缺失。当前 `records.ts` 已计算或返回最近沟通、下一次跟进、客户 / 项目关系、订单已收与应收、收款状态及任务等数据；主要遗漏发生在页面没有把这些结果按 demo 的方式组织出来。任务分组和历史日期筛选则需要补足对应的查询 / 页面状态编排。
3. Demo 使用不同的本地存储与桌面运行栈，当前版本使用 Next.js 与 Prisma。两者之间的差异要求增加当前栈内的 UI 映射与 API 适配，不构成更换 Next.js 架构的理由。
4. 当前统一字段编辑器把资料链接作为文本解析，无法提供 demo 的逐条新增 / 删除体验；复盘也缺少专用 Markdown 展示。应在当前页面层补专用控件和渲染，不改动现有字段名或丢弃旧值。

### 目标标准与当前栈迭代原则

- 保留现有菜单名称、字段名称、Prisma 数据键、业务编号、API 安全校验、软删除与记录版本规则。截图术语仅做页面 / 功能映射，不做改名任务。
- 保留 Next.js、Prisma 和现有服务边界；在 `guangyu-space` 模块内按页面增加内容页签、实体列表列配置、专用表单 / 详情区块。通用抽屉和按钮基础样式可复用，但不要求所有业务复用同一张表格或字段排布。
- 资料链接使用结构化逐条编辑控件，并通过当前数据键兼容读取、保存已有文本格式或已有记录；不得因 UI 改造删除旧链接或其他当前字段。
- 详情复制面向用户复制可见业务编号，不复制内部数据库 UUID。关联快捷操作沿用现有 API 与表单，完成后刷新对应详情和列表。
- 列表按 demo 配置列头排序与 20 / 50 / 100 每页选项，默认 50；任务按类型 / 区域与项目分组，加入日期历史筛选。复盘使用当前周期页签驱动筛选、默认类型和 Markdown 阅读。
- Demo 和截图未出现的当前字段仍保留原字段名与已有数据；主界面优先呈现目标信息，额外字段继续在当前表单或详情中可维护，不因视觉复刻而静默丢弃。
