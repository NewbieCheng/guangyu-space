## 1. 产品定位与设计目标

### 1.1 品牌表达

| 项目 | 已确认内容 |
|---|---|
| 产品名称 | 光域空间 |
| 品牌来源 | 光域工作室 |
| Slogan | 让事业，多一种可能 |
| 产品用途 | OPC 经营管理工具 |
| 主要人群 | OPC、一人公司、独立创业者和个人经营者 |
| 品牌寓意 | “光”代表 AI 带来的新机会 |
| 工作方式 | 用户通过可视化界面管理经营数据，也可授权 Agent 读取与写入同一份业务记录 |

产品介绍：光域空间是光域工作室打造的 OPC 经营管理工具，面向一人公司、独立创业者和个人经营者。品牌中的“光”象征 AI 带来的新机会，产品名称延续工作室的品牌与寓意。产品将客户、订单、财务、项目任务、经验沉淀和能力提升集中在一个可视化的经营空间中，帮助用户看清业务、组织行动、积累成果。用户既能通过界面直接管理业务，也能借助 Agent 读取和更新经营记录，让人与 AI 围绕同一份业务信息协作。品牌 Slogan 是“让事业，多一种可能”。

### 1.2 第一版范围

第一版为个人版：继承原 App v1.0–v1.4 的全部已确认业务功能，增加用户登录和账号密码管理，使用通用菜单及业务名称。多个独立用户在线使用各自的数据。

技术方向为 Next.js 全栈＋PostgreSQL。多人协作、团队版、项目成员及权限结构按数据库规则预留，第一版页面只承载个人业务和已确认账号功能。

外部资料采用指针与链接管理。网页链接、Obsidian 笔记和普通本地文档的打开能力保留；普通本地文档一键打开是第一版必做项，用户已接受安装本机配套工具。

本文件负责视觉与交互呈现，功能、数据归属、权限、统计和状态的业务含义由以下文件确定：

- [第一版功能需求整合](第一版功能需求整合.md)：第一版功能与原版交互基线。
- [数据库搭建规则参照](数据库搭建规则参照.md)：数据归属、金额、历史记录、授权与一致性规则。
- [模块与字段命名清单](模块与字段命名清单.md)：已确认菜单、品牌、字段、操作和状态名称；业务编号沿用原格式。

视觉调整保持上述功能与业务口径。账号采用用户名＋密码、自助注册及人工找回；备份入口使用“备份数据／恢复数据”，遵守本人回滚与恢复前快照确认规则。

框架首选 Velobase Harness；AI SaaS 的未来能力保留在架构中。第一版导航、页面和文案按个人经营管理范围呈现，框架模板页面不作为本产品设计基线。

### 1.3 界面设计目标

光域空间是日常经营工具。界面优先服务阅读、录入、跟进、交付和复盘，整体清爽简约、层次清楚，能够长时间处理表格和文字。

科技与宇宙感通过月球星环 Logo、紫青玫瑰配色和细节体现。工作区域采用明亮的雾灰底、白色内容面与平面控件，信息按标题、分组、对齐和留白组织。

### 2.2 图形语言与颜色关系

Logo 由浅灰月球、紫色星环、金色星芒构成；完整版本带“光域空间”深色字标。Logo 的月球立体感、星环渐变、金色星芒和字标均按原图呈现。

### 2.3 展示规范

- 完整 Logo 保持 3:1 画布比例，Icon 保持 1:1 画布比例；等比缩放、完整呈现，保留月球、完整星环与星芒。
- 品牌区使用浅色底。Logo 与旁边的导航、文字之间保持至少 12px 间距；实际图形周围保留可识别的呼吸空间。
- 登录页完整 Logo 的展示框建议宽 320–420px；桌面导航中的完整 Logo 展示框控制在导航内宽，建议 200–216px。按有效字标的清晰度验收，而非只看画布尺寸。
- 紧凑品牌入口建议展示 Icon 32–40px；当前原图的留白会影响有效图形尺寸，需在实际页面核对。
- Logo 用作导航入口时，提供“光域空间，返回经营总览”的可访问名称。纯展示的完整 Logo 提供“光域空间”替代文本。
- 同一区域中的完整 Logo 与独立 Icon 按空间择一使用；完整 Logo 已包含图标和字标。

### 2.4 当前素材的适配说明

两份源图都有较多画布留白，且不含透明通道。它们可用于浅色品牌展示，但紧凑导航与 16px、32px 浏览器图标需要单独核对辨识度。

## 3. 星云配色系统

### 3.1 已确认主色板

方案名称：**星云：紫＋青＋玫瑰 · 科技感，层次鲜明**。

| 色彩角色 | 名称 | 色值 | 使用范围 |
|---|---|---|---|
| 主要交互色 | 星云紫 | `#6650A5` | 主要按钮、当前导航、选中控件、默认业务链接、键盘焦点 |
| 辅助色 | 极光青 | `#197F76` | 辅助区块标记、适用的辅助链接及成功／完成反馈 |
| 局部点缀色 | 玫瑰 | `#A05C76` | 少量分类标签、经营资产细节和品牌辅助点缀 |

色彩按组件角色复用。主要操作以紫色建立稳定识别；青与玫瑰用于少量辅助信息，模块主要通过名称和导航层级识别。

| `surface-muted` | `#ECECEC` | 次级分区、工具条、禁用控件底色 |
| `text-primary` | `#262626` | 正文、名称、金额、主要标题 |
| `text-secondary` | `#666666` | 系统时间、编号说明、辅助文字 |
| `text-placeholder` | `#707070` | 白底输入控件的提示文字 |
| `border-subtle` | `#DDDDDD` | 表格分隔线、普通卡片边界 |
| `control-border` | `#8A8A8A` | 需要边框识别的输入、勾选及选择控件 |
| `primary` | `#6650A5` | 主要操作和选中标记 |

### 3.3 业务状态与反馈

| 信息类型 | 呈现方式 | 前景／背景基线 |
|---|---|---|
| 进行中、当前选中、一般信息 | 紫色标记或浅紫底，并展示具体状态文字 | `#6650A5`／`#EEEAF7` |
| 已完成、保存成功、已收齐 | 青色图标或浅青提示 | `#126B64`／`#E6F2F0` |
| 等待中、未开始、待确认、已放弃、已取消、已删除 | 中性灰标签，逐项保留准确文字 | `#666666`／`#ECECEC` |
| 逾期、需要补录、需要注意 | 警示图标与文字；必要时使用浅警示底 | `#8A6016`／`#FFF4DC` |
| 校验错误、保存失败、危险操作 | 错误图标和明确原因，破坏性动作使用红色 | `#B42318`／`#FEECE8` |
| 自由分类与经验标签 | 必要时使用少量玫瑰标签 | `#85465F`／`#F5E8EE` |

警示与错误色属于语义反馈色。业务状态的含义、选项数量、日期判断和汇总逻辑沿用功能与数据库规则。

“未收款”或“部分收款”本身是业务事实；只有符合业务口径的逾期或异常才加警示。项目状态、订单交付状态、收款状态分别展示。

状态同时使用文字、图标或位置表达含义。任务优先级仍展示“高／中／低”或最终确认用语，保持原 P0／P1／P2 排序。

## 4. 排版、间距与界面质感

### 4.1 字体与字号

界面使用系统无衬线字体，兼顾 Mac 与 Windows。推荐顺序：系统 UI 字体、PingFang SC、Microsoft YaHei、通用 sans-serif。品牌字标使用完整 Logo 图形。

| 层级 | 执行基线 |
|---|---|
| 默认业务正文、列表主要内容、按钮与输入 | 16px，常规字重，行高约 24px |
| 首页内容区与空状态 | 固定 16px，继承 v1.1 的阅读要求 |
| 新增、编辑、详情中的字段标题和内容 | 均为 16px；字段标题字重 600 |
| 页面主标题 | 建议 24px／32px，字重 600 |
| 区块与抽屉标题 | 16–20px，字重 600，按层级固定使用 |
| 系统编号、时间、非关键辅助说明 | 建议 14px；关键金额、操作和状态仍采用 16px |
| 复盘、经验等长文正文 | 16px，行高约 28px，清楚区分段落和标题 |

首页累计收入通过位置、字重、对齐与留白突出，遵循既有首页内容的 16px 口径。金额右对齐、数字采用等宽数字排版，保留未知金额与零的区别。

### 4.2 间距与形状

- 间距采用 4px 基准，主要使用 8、12、16、24、32px。
- 桌面内容区边距建议 24px，区块间距 16–24px，卡片内边距 16–24px。
- 标准输入和主要按钮建议高 44px；密集工具条可用 40px，触屏保持足够点击区域。
- 按钮和输入圆角建议 6px，内容卡片建议 8px，弹窗建议 12px；同类组件统一。
- 普通内容面以背景和细分隔线组织层次。抽屉、弹窗使用轻阴影和遮罩表达覆盖关系。
- 图标采用统一的线性风格。普通图标建议 18–20px；品牌 Icon 按第 2 节使用。

### 4.3 色彩与空间的关系

雾灰与白色承担大面积工作区域。紫色集中于主要操作与当前位置；青色用于辅助区块或成功反馈；玫瑰用于少量标签。长文、金额、项目名称与字段内容以深色文字保证稳定阅读。

Logo 的星环和月球负责品牌形象。业务列表、表单和复盘正文使用清楚的平面排版，保持高信息密度下的可读性。

## 6. 核心组件与交互规范

### 6.1 按钮与链接

| 操作层级 | 样式 | 使用原则 |
|---|---|---|
| 当前主要动作 | 紫底白字 | 当前操作区突出一个主要提交或新增动作 |
| 次要动作 | 白底深字，必要时使用紫色边框 | 编辑、返回、取消及适用关联操作 |
| 辅助业务动作 | 青色文字或适用的青色按钮 | 辅助入口按层级使用，保持白字对比度 |
| 删除等危险动作 | 红色图标／文字，确认提交使用危险色 | 按已有删除与恢复规则执行 |
| 小图标操作 | 中性图标及可访问名称 | 复制编号、复制 ID、关闭等 |

主要按钮默认 `#6650A5`，悬停 `#584193`，按下 `#49357F`；文字白色。焦点使用清楚的紫色外环，并与控件留出约 2px 间隔。禁用态以中性灰呈现；加载时保留操作名称并防止重复提交。

同一保存、取消、删除、恢复动作在不同模块保持样式一致。控件默认、悬停、焦点、按下、禁用和加载状态分别定义。

### 6.2 表格、卡片与筛选

- 表头、记录行与操作位置对齐；表格使用细水平分隔线，长文本按内容类型处理。
- 悬停行使用轻微中性底色；选中行使用浅紫底，并通过勾选或当前位置明确表达。
- 卡片按原功能分组；统一标题、主体、状态和操作位置。
- 搜索、筛选、排序、分页及适用历史入口按功能文件实现，操作后保留相应列表上下文。
- 日期按北京时间展示和筛选；金额按人民币元显示，计算口径来自数据库规则。

### 6.3 表单

- 字段标签位于输入上方；必填同时使用文字或标记表达，保留 16px 字段字号。
- 一组字段使用一致的控件高度、间距和对齐；长文本、备注和 Markdown 正文提供适当阅读与录入空间。
- 未知金额显示对应待录入提示；不能因占位或样式把未知金额呈现为零。
- 校验错误放在对应字段附近，并保留已输入内容。保存失败与版本冲突明确说明原因。
- 关联选择保持原有搜索和选择机制，已删除关联对象展示准确状态。

### 6.4 详情抽屉与弹窗

继承原版已确认行为：

- 桌面详情使用右侧覆盖式抽屉，宽约可用窗口的 60%；小屏占满可用宽度。保持底层列表布局与上下文。
- 抽屉背景白色，标题与操作区清楚，内容独立滚动；滚动长正文时仍能找到关闭与主要操作。
- 阅览态可点击抽屉外关闭。新增、编辑和有草稿的状态按原规则保护未保存内容。
- 沟通追加、项目日志追加等沿用独立弹窗；日期和内容按原需求录入。
- 弹窗遮罩位于抽屉之上；关闭弹窗回到原详情。遮罩、关闭按钮与键盘关闭遵循当前层级及草稿保护。
- 未保存退出按原功能提供继续编辑、放弃或保存后继续；保存失败继续保留草稿。

对话框提供清楚标题和焦点管理；关闭后焦点回到触发入口。具体操作名称以命名清单的最终确认内容为准。

### 6.5 加载、空状态与异常

- 列表和详情加载保留结构，展示简洁的加载提示或骨架。
- 新用户经营数据为空，按各模块展示真实空状态与已有新增入口。
- 无搜索结果说明当前筛选无匹配记录，保留清除筛选的已有交互。
- 网络、校验、登录过期及版本冲突分别呈现，用户可以辨认问题并继续已有流程。
- 操作成功使用轻量青色反馈；操作失败在当前上下文说明原因，保护录入内容。
- 成功、失败、危险确认均以文字和可见状态表达含义。

### 6.6 动效

交互过渡建议 150–200ms，用于抽屉、弹窗、控件反馈和状态变化。优先保持内容与操作稳定；遵循系统减少动态效果偏好。

### 6.7 资料链接的界面呈现

- 项目及适用记录详情中的添加资料入口，录入资料名称和地址，保存为资料索引。资料库继续管理原有分类、用途及关联。
- 链接列表明确展示名称、地址和地址类型：网页、本地文档、Obsidian。类型可由地址识别，不因此新增需要用户维护的分类体系。
- 网页入口为“打开网页”，Obsidian 入口为“打开笔记”，普通本地文档入口为“打开文档”；这些是本次资料功能补充的操作文案，沿用统一按钮层级。
- 当前设备首次使用本地文档打开功能时，提供配套工具安装说明；同时保留“复制地址”和更正地址的入口。一键打开按功能文件验收。
- 文件找不到、配套工具尚未安装、目标应用或笔记不可用时，展示对应处理说明，保留原索引。浏览器未提供可靠结果时，提示“已发送打开请求”，避免呈现未经证实的打开成功。
- 表单和详情围绕名称、指针、链接与关联排版；外部文件由用户在原位置保管，界面不出现文件上传区或云端文件预览器。
- UI 操作只维护索引，删除、恢复和修改地址按功能文件执行；具体本机工具形态和状态回传方式由技术设计确定。

## 8. 可读性与可访问性验收

普通文字和实际背景的对比度以至少 4.5:1 为基线；识别控件或状态所必需的非文字视觉信息与相邻颜色至少 3:1。依据 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)和 [W3C 非文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)。

下列颜色对已按不透明 sRGB 色值计算；数值为显示时四舍五入的参考，不代表整套界面已经通过验收：

| 前景／背景 | 对比度约值 | 用途 |
|---|---|---|
| 紫 `#6650A5`／白 `#FFFFFF` | 6.45:1 | 主按钮白字、白底紫色链接 |
| 紫 `#6650A5`／浅紫 `#EEEAF7` | 5.45:1 | 紫色选中标签 |
| 青 `#197F76`／白 `#FFFFFF` | 4.84:1 | 白底青色文字、青底白字 |
| 深青 `#126B64`／浅青 `#E6F2F0` | 5.53:1 | 完成和成功标签 |
| 深玫瑰 `#85465F`／浅玫瑰 `#F5E8EE` | 5.81:1 | 标签文字 |
| 辅助灰 `#666666`／雾灰 `#F4F4F4` | 5.22:1 | 辅助文字 |

验收时核对实际颜色、字号、背景、透明度与交互状态：

- 主按钮及所有正常可操作文字清楚可读，浅色标签配足够深的文字。
- 关键状态附带准确文字，图标按钮有可访问名称，键盘焦点可见。
- 通过键盘完成已有核心流程，弹窗与抽屉保持正确焦点和草稿保护。
- 200% 缩放及代表性小屏宽度下，主要内容和操作仍可用。
- 两份 Logo 在实际展示尺寸下检查字标、月球、星环及星芒的识别性。
- 首页、表单、详情及长文遵守已确认字号和布局要求。
- 验收采用虚构业务数据，品牌资产采用本项目收录的正式源图。
