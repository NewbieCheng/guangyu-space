# 光域空间本地部署与安全运维

## 1. 本地开发环境

本机运行 Node.js 22 Web 服务，Docker 仅运行 PostgreSQL 16 和 Redis 7。仓库中的本地 Compose 覆盖文件将端口绑定到回环地址：PostgreSQL `127.0.0.1:54333`，Redis `127.0.0.1:56380`。默认数据库用户和口令只供本机开发使用。

首次启动：

1. 复制 `.env.example` 为根目录 `.env`。Prisma 配置和 Next.js 都从 `.env` 读取。
2. 设置随机 `AUTH_SECRET`。Mac/Linux：`openssl rand -base64 48`；Windows PowerShell：`node -e "console.log(require('node:crypto').randomBytes(48).toString('base64'))"`。不要提交 `.env`。
3. 启动 PostgreSQL 和 Redis：

   ```sh
   docker compose -f docker-compose.yml -f compose.local.yml up -d postgres redis
   ```

4. 安装、迁移、启动：

   ```sh
   corepack pnpm install --frozen-lockfile
   corepack pnpm db:migrate
   corepack pnpm dev
   ```

访问 `http://localhost:3000` 并注册账号。Windows 可以编辑 `.env` 后运行 `scripts/start-local-windows.bat`。该脚本启动同一套数据库服务、安装依赖、部署迁移并运行开发服务。它需要 Docker Desktop 已启动。

停止 Web 按 `Ctrl+C`。停止容器并保留数据库：

```sh
docker compose -f docker-compose.yml -f compose.local.yml down
```

不要使用 `down --volumes`，那会删除本机数据库卷。

## 2. 运行边界

应用默认 `SERVICE_MODE=web`。第一版不配置或启用 Harness 的计费、支付、邮件、营销、分析、AI、广告、触达、联盟、支持自动化、网关或云存储服务。健康检查只报告服务状态，不返回密钥、连接串或运行环境详情。

真实经营记录、个人备份和本机资料路径都属于敏感数据。不要提交 `.env`、`data/`、数据库导出、个人备份或真实业务资料；开发演示请使用虚构内容。

## 3. 本机资料打开工具

资料记录保存网页链接、Obsidian URI 或本机路径指针，不上传本机文件正文。

### macOS

需要 Xcode Command Line Tools 中的 Swift 编译器。执行：

```sh
sh tools/local-open-helper/macos/install.sh
```

工具安装到当前用户的 `~/Applications/GuangyuOpenHelper.app`，并注册 `guangyu-open://` 协议。浏览器首次打开该协议时会询问是否允许启动本机工具；工具会显示系统是否已将文件或文件夹交给默认应用处理，以及具体失败原因。

### Windows

需要 .NET 8 SDK。PowerShell 在仓库根目录执行：

```powershell
dotnet publish tools/local-open-helper/windows/GuangyuOpenHelper.csproj -c Release -r win-x64 --self-contained true -p:PublishSingleFile=true -o tools/local-open-helper/windows/publish/win-x64
powershell -NoProfile -ExecutionPolicy Bypass -File tools/local-open-helper/windows/install.ps1 -ExecutablePath tools/local-open-helper/windows/publish/win-x64/GuangyuOpenHelper.exe
```

安装脚本只为当前 Windows 用户注册协议，不需要管理员权限。浏览器会在首次启动时征求确认；工具只接受当前设备的绝对文件/文件夹路径，并显示打开成功或失败。Windows 源码和安装说明已提供；本工作区未在 Windows 上运行验收。

## 4. 个人备份与恢复

登录后进入“账号设置 → 个人备份与恢复”。下载的 JSON 备份包含本人经营记录、私有内容、关联、资料指针和编号序列，不包含密码、登录会话、Agent 密钥、审计历史或本机文件正文。

恢复流程会校验账号与经营簿归属、记录格式和记录数量；在确认前将当前数据写入 `GUANGYU_BACKUP_DIR` 指定目录，默认是仓库 `data/backups/`。用户二次确认后再应用恢复，恢复操作会创建最新保护快照、保留编号序列高水位、清除幂等缓存、撤销 Agent 授权并让旧网页登录会话失效。应用快照目录必须位于有访问控制的本机持久化磁盘；恢复前确认剩余空间充足。

这份 JSON 适合个人数据迁移和逻辑恢复，不能替代 PostgreSQL 完整备份。恢复失败时先保留原始 JSON、当前数据库和 `data/backups/`，再检查应用日志；不要手工删改备份内容后直接恢复。

## 5. PostgreSQL 每日备份（保留 7 天）

仓库提供数据库级备份脚本。数据库容器和 Docker Desktop 必须处于运行状态。

macOS/Linux 手动执行：

```sh
sh scripts/backup-postgres.sh
```

Windows PowerShell 手动执行：

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File scripts/backup-postgres-windows.ps1
```

默认输出到 `data/postgres-backups/`，只保留最近 7 天的 `guangyu-postgres-*.dump`。设置 `GUANGYU_DB_BACKUP_DIR` 可改用另一持久化目录。将备份同步到设备外的加密存储，并限制读取权限；本脚本本身不执行远程同步。

需要每日运行时，在 macOS/Linux 用当前操作系统账号配置 cron，在 Windows 任务计划程序配置每天触发对应脚本。定时任务应以可访问 Docker Desktop 的同一用户运行；主机休眠或 Docker 未运行时，任务不会产生有效备份。首次设置后手动运行一次并检查 dump 非空。

### PostgreSQL 恢复

恢复会覆盖同名数据库中的业务数据。先停止 Web，复制一份当前 `.dump` 到安全位置，再针对目标实例执行 `pg_restore --clean --if-exists --no-owner`。恢复后部署当前仓库迁移并检查用户、登录、记录数量及金额汇总。恢复前确认目标实例和备份日期，不要把另一套环境的备份导入当前经营簿。

## 6. 账号和 Agent 运维

- 用户名全局唯一；密码至少 12 个字符，UTF-8 编码不超过 72 字节。
- 用户修改密码会核验当前密码、更新账号授权版本并撤销其现有 Agent 凭据。应用不提供公开的密码重置接口。
- 首个管理员账号只通过已注册账号、当前密码、身份核验说明和显式确认进行一次性引导：`corepack pnpm exec tsx scripts/admin/bootstrap-first-admin.ts`。已存在管理员时该引导会拒绝运行。
- 管理员在交互式终端为账号重置密码：`corepack pnpm exec tsx scripts/admin/reset-account-password.ts`。管理员用户名、当前密码、目标账号和复核原因由终端逐步收集；新临时密码通过隐藏输入读取，不接受命令行参数，也不会写入日志或审计。操作会撤销目标账号的网页登录会话和 Agent 凭据。
- Agent 凭据仅在网页账号设置中签发；密钥只返回一次。按需给最小范围和期限，离职/泄露/迁移后立即撤销。

API 路径、范围和数据契约见 [`Agent-API.md`](./Agent-API.md)。

## 7. 自托管部署

Mac/Windows 本地启动流程可作为单机部署起点。对外开放前必须：

1. 为 PostgreSQL、Redis 和 `AUTH_SECRET` 设置独立强凭据，确认数据库与 Redis 不直接暴露公网。
2. 使用 HTTPS 反向代理，设置正式 `APP_URL` / `AUTH_URL`、`COOKIE_SECURE=true`，应用仅接受受信代理转发的来源。
3. 使用持久化 PostgreSQL 和 Redis 数据目录；将 `GUANGYU_BACKUP_DIR` 与数据库备份目录放在持久化磁盘并限制访问权限。
4. 执行 `corepack pnpm db:migrate`，以 `corepack pnpm build` 构建，再以进程管理器运行 `corepack pnpm start`。不使用 `db:push` 替代迁移。
5. 配置每日 PostgreSQL dump、7 天本机轮转和加密异地副本；定期演练数据库和个人 JSON 两种恢复流程。
6. 保持所有第一版未启用的框架模块关闭，并审查反向代理、操作系统防火墙、日志脱敏、磁盘空间和备份可读性。

本说明和 Windows 源码描述目标路径，不表示 Windows 或生产环境已经验收。上线前需在目标操作系统、数据库和网络环境完成完整演练。
