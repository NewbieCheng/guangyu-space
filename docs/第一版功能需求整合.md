# 光域空间 · 第一版功能需求整合

整理日期：2026-10-14（Asia/Shanghai）  
版本：光域空间 v0.1.0。  
状态：功能、显示名称、账号方案、个人备份回滚、资料打开及框架首选已确认，可用于技术交接；尚未开发。  
用途：将原 App v1.0–v1.4 的功能整合为网页版个人版的功能基线。实施入口见 [v0.1.0 技术 Agent 施工提示词](v0.1.0技术Agent施工提示词.md)。

视觉执行依据：[产品设计文档](产品设计文档.md)，包含已确认的两份 Logo、星云配色及 UI 规范。

## 1. 第一版范围

已确认：

1. 原 App v1.0–v1.4 的全部业务功能作为网页版第一版的基线，包括当前主线中的经验宝箱、产品宝箱。
2. 增加用户登录和账号密码管理。
3. 将游戏化菜单、子菜单、模块、字段和相关操作用语改为通用名称，由辣辣确定最终名称。
4. 使用 Next.js 全栈和 PostgreSQL；第一版只实现个人版，多个独立用户使用各自数据。
5. 按[数据库搭建规则参照](数据库搭建规则参照.md)预留多人协作及团队版框架，第一版不开放团队功能。
6. 除上述范围及网页运行所需的适配，不扩展新业务功能。
7. 外部资料采用指针与链接管理，文件由用户在本地或原网站保管。第一版必须支持普通本地文档一键唤起，用户已接受安装本机配套工具；此工具属于资料打开的网页适配范围。

名称修改不改变业务含义、字段用途和已有数据关系。本文件保留原名称以精确对应来源，实际界面使用[模块与字段命名清单](模块与字段命名清单.md)中已确认的新名称。业务编号沿用原格式。

首选 Velobase Harness，保留 AI SaaS 的源码与扩展能力，第一版只启用个人经营管理所需能力。“最小 MVP”约束运行服务、外部依赖和新增功能，不削减本文已确认的业务继承范围。选型证据、启用边界和许可见 [v0.1.0 需求记录](v0.1.0需求记录.md)。

原 Mac 的启动项、菜单栏、安装包和本机文件打开属于桌面载体能力；网页版按第 12 节承接其用途，不开发另一套桌面外壳。

## 4. 共用功能与交互

来源：S0、S1、S2、SC。

### 4.1 列表与详情

- 各主业务模块支持新增、读取详情、编辑、保存、取消、搜索、适用的筛选、排序和分页。
- 点击记录或新增入口，在右侧覆盖式抽屉中操作，宽度约为窗口的 60%。
- 新增成功后抽屉保持打开，转为新记录详情；编辑成功后返回详情，列表和相关汇总刷新。
- 关闭抽屉回到原列表，保留搜索、筛选、排序和分页上下文。
- 详情阅览状态可点击抽屉外区域关闭；新增和编辑状态保护未保存内容。
- 弹窗与底层抽屉各自处理遮罩及关闭操作，操作弹窗不连带关闭详情。
- 有未保存修改时，提供继续编辑、放弃修改或保存后继续的选择；保存失败保留输入。
- 关联选择通过已有记录搜索和选择，保存 ID 关系。
- 业务 ID 可在详情查看、复制；系统生成创建时间、更新时间和版本。
- 普通字段局部更新区分“未提交”和“明确清空”。

### 4.2 操作与删除

- 详情顶部集中放置编辑及适用的关联待办、沟通、日志、资料操作。
- 删除和复制 ID 使用较小的图标按钮，悬停提示名称，保持可操作的点击区域及可访问名称。
- 删除前确认；可查看已删除记录并恢复，保留 ID 和关联，关联对象已删除时给出清晰提示。
- 完成、放弃、取消、删除分别表达不同业务含义。
- 用户与 Agent 操作后，相关列表、详情和首页重新读取统一结果。

### 4.3 阅读与布局

- 原首页指定内容区及空状态文字固定为 16px。
- 新增、编辑和详情中的字段标题与内容均为 16px，字段标题加粗。
- 保留模块子标题，去掉子标题下的说明文字；搜索框和新增按钮同一行对齐。
- 网页视觉采用已确认的“星云：紫＋青＋玫瑰”方案，雾灰底、白色内容面，以及光域空间品牌 Logo；具体颜色、排版和组件规范见[产品设计文档](产品设计文档.md)。
- 复盘正文使用长文阅读版式，区别于普通记录的键值详情表格。

## 5. 客户与合作方

### 5.1 客户

来源：S0、S1、S2、SC。

| 字段类型 | 原字段与行为 |
|---|---|
| 身份 | 客户 ID 系统生成；客户名称必填，客户可为个人或公司 |
| 业务信息 | 行业／业务领域、客户来源、需求说明、备注、多条资料链接 |
| 客户状态 | 潜在客户、洽谈中、合作中、历史客户、暂不跟进 |
| 沟通 | 追加沟通记录，展示最近沟通时间 |
| 跟进 | 关联农活／跟进农活，自动展示下一次跟进 |
| 业务关联 | 关联项目、关联订单 |
| 财务汇总 | 累计到账、当前应收，来源于有效订单和收入规则 |
| 系统信息 | 创建时间、更新时间、版本、删除标记 |

列表优先展示名称、状态、最近沟通、下一次跟进、关联项目；当前界面还显示创建时间。

客户详情提供添加农活、追加沟通、独立添加资料等入口。添加农活时自动关联当前客户，项目可不填。

### 5.2 合作方

来源：S0、S1、S2、SC。

| 字段类型 | 原字段与行为 |
|---|---|
| 身份 | 合作方 ID 系统生成；合作方名称必填 |
| 业务信息 | 行业／业务领域、资源与能力、合作说明、备注、多条资料链接 |
| 合作状态 | 待接洽、洽谈中、合作中、历史合作、暂停合作 |
| 合作方向 | 支持多选；当前选项为资源互补、联合交付、渠道合作、内容合作、顾问支持、其他 |
| 沟通与跟进 | 沟通记录、最近沟通、下一次跟进、关联农活 |
| 关联 | 关联项目 |
| 系统信息 | 创建时间、更新时间、版本、删除标记 |

客户与合作方分别保存。合作方详情提供添加农活和追加沟通；关联创建时自动带入当前合作方。

### 5.3 追加沟通

- 客户、合作方详情顶部提供沟通追加入口，位于关联任务新增入口旁；按钮按产品设计文档的操作层级使用统一配色，名称以命名清单最终确认内容为准。
- 独立弹窗录入日期和沟通重点；日期默认北京时间当天，可修改。
- 日期和非空内容必填；每次确认保存一条独立记录。
- 保存成功关闭弹窗，详情保持打开，刷新沟通记录及最近沟通。
- 取消不写入，失败保留草稿，重复提交和重试不重复新增。
- 草稿绑定打开弹窗时的对象类型及 ID，不能因切换记录写错对象。

### 5.4 独立添加资料

- 客户及所有项目详情提供“添加资料”，不要求整条记录进入编辑状态。
- 只在链接区域录入资料名称和链接地址，其他信息保持阅览状态。
- 资料地址可指向网页、本地文档或 Obsidian 笔记，按第 9.1.1 节的打开规则处理；添加资料只保存索引，文件留在原位置。
- 保存只追加链接，保留已有链接及其他字段；更新系统版本和更新时间。
- 保存成功收起录入区域，保持原链接展示方式；取消无写入，失败保留输入。
- 版本冲突时保留链接草稿并展示最新记录，不以旧链接列表覆盖其他修改。

## 6. 项目、能力提升项目及进展日志

### 6.1 通用项目

来源：S0、S1、S2、S3、SC。

| 字段类型 | 原字段与行为 |
|---|---|
| 身份 | 项目 ID 系统生成；项目名称必填 |
| 所属区域 | 农田、加工间、牧场、矿洞、森林海滩、铁匠铺；名称待调整 |
| 项目状态 | 未开始、进行中、等待中、暂停、已完成、已放弃 |
| 项目信息 | 项目说明、目标／预期产出（包含完成标准）、备注、资料链接 |
| 日期 | 开始日期、目标完成日期 |
| 关联 | 客户、合作方、订单；各关系支持多个关联对象 |
| 子记录 | 所属农活、耕种日志 |
| 系统信息 | 创建时间、更新时间、版本、删除标记 |

五个项目区域和铁匠铺共用项目表。项目改名、改区域后保留 ID 及关联。

从项目详情添加农活时自动关联当前项目；该农活同时出现在全局农活页，使用同一条记录。项目状态操作不自动改变农活状态；已完成或暂停项目可以重新进入进行中。

### 6.2 克林特的铁匠铺

- 管理个人学习、工具升级、系统维护项目，复用通用项目及农活机制。
- 增加“升级类型”字段：学习、工具升级、系统维护。
- 从该模块新建时，所属区域默认铁匠铺，升级类型当前默认学习。
- 项目下可添加农活、资料和进展日志。
- 网页版此类能力提升内容按已确认规则归属于个人账号，其他用户不可见。

### 6.3 耕种日志

来源：S3、SC。

- 所有项目提供“耕种日志”展示区和“追加耕种日志”弹窗入口。
- 录入日志日期、项目进展；日期默认北京时间当天，可修改；日期及非空内容必填。
- 同一天允许多条日志，每次确认保存独立记录。
- 日志按日志日期倒序，同日按创建时间倒序并采用稳定次级排序；补录按实际日志日期归位。
- 保存成功关闭弹窗，详情保持打开；取消不写入，失败保留草稿，重试不重复创建。
- 草稿绑定打开时的项目，日志保存不修改项目其他字段或状态。
- 项目改名、调整区域、删除及恢复时保留日志和关联；已删除项目不接受新日志追加。
- 当前原 App 的日志能力是追加与读取，不提供日志编辑、删除入口；已讨论的团队编辑与删除权限只作为后续框架保留。

## 7. 农活及历史农活

来源：S0、S1、S4、SC。

### 7.1 数据与操作

| 字段类型 | 原字段与行为 |
|---|---|
| 身份 | 农活 ID 系统生成；农活名称必填 |
| 关联 | 所属项目选填；关联客户或合作方，支持无项目跟进事项 |
| 状态 | 待办、进行中、等待中、已完成、已放弃 |
| 优先级 | P0 高、P1 中、P2 低；默认 P1 |
| 日期 | 计划日期、截止日期；当前新增计划日期默认当天 |
| 内容 | 说明、备注、多条资料链接 |
| 自动信息 | 完成时间、所属项目名称及状态、从项目获取的经营区域 |
| 系统信息 | 创建时间、更新时间、版本、删除标记及完成前状态 |

- 列表和首页可直接勾选完成；也可取消完成。
- 取消完成恢复完成前状态并清空当前完成时间，再次完成记录新的完成时间。
- 可搜索，按区域、项目、状态筛选；支持编辑、删除恢复。
- 账号私有个人待办、客户跟进待办、项目待办按数据库规则确定归属。

### 7.2 当前农活面板

- 按农田、加工间、牧场、矿洞、森林海滩、铁匠铺六个分组展示，每组一张大卡片，顺序固定；最终名称待调整。
- 区域来自所属项目当前区域；区域内按项目编号升序，将同项目农活集中展示。
- 同项目内先按 P0、P1、P2，再按计划日期从早到晚；同优先级无计划日期的排在有日期之后。
- 相同条件采用稳定次级排序，分组和分页不能导致遗漏、重复或错误空状态。
- 无项目农活放在底部“未归属”卡片，包括尚未关联项目的客户或合作方跟进事项。
- 已完成农活默认从当前面板移除，记录保留；取消完成后按规则重新出现。

### 7.3 历史农活

- 提供“查看历史农活”按钮，打开独立抽屉。
- 初次打开显示全部已完成农活，按实际完成时间从最近到最早平铺，不按项目分组。
- 只展示农活名称、所属项目、完成日期；未关联项目清楚显示为空。
- 提供“全部农活”按钮及日期组件；日期组件默认定位当日，选择日期后显示该日完成记录。
- “全部农活”清除日期过滤；筛选依据实际完成时间的北京时间日期，不依据计划或截止日期。
- 空结果、加载状态和失败提示明确；相同完成时间采用稳定次级排序。

## 8. 订单与收入流水

来源：S0、SC。

### 8.1 订单

| 字段类型 | 原字段与行为 |
|---|---|
| 身份 | 订单 ID 系统生成；订单名称必填 |
| 客户 | 关联一位客户，必填 |
| 内容与项目 | 订单内容、关联一个或多个项目、资料链接、备注 |
| 订单／交付状态 | 待确认、执行中、已交付、已取消 |
| 约定金额 | 订单金额，允许暂未录入 |
| 日期 | 下单日期、约定交付日期 |
| 自动金额 | 已收金额、应收金额 |
| 收款状态 | 未收款、部分收款、已收齐；交付和收款分别展示 |
| 系统信息 | 创建时间、更新时间、版本、删除标记 |

订单已收金额汇总有效收入，应收为订单金额减已收。未知金额显示待录入，多收显示实际多收，不修改真实到账金额。

### 8.2 收入流水

| 字段类型 | 原字段与行为 |
|---|---|
| 身份 | 收入 ID 系统生成；收入名称可填 |
| 日期和金额 | 实际到账日期、实际到账金额必填，金额必须为正 |
| 关联 | 可关联一张订单，也可登记独立收入 |
| 收款方式 | 当前选项微信、支付宝、银行转账、现金、其他 |
| 内容 | 资料链接、备注 |
| 系统信息 | 创建时间、更新时间、版本、删除标记 |

- 一张订单可关联多笔收入。
- 更正、删除、恢复或调整关联后，订单、客户及首页相关金额重新汇总。
- 删除客户或订单保留已发生收入及历史归属，删除收入才将其从有效统计中剔除。
- 金额按整数分保存及传输，界面按人民币元展示；零和未知金额区分。
- 独立收入也计入累计收入及对应月份到账。
- 取消订单保留实际收入；当前应收与历史到账分别计算。

### 9.1.1 外部资料的指针与打开规则

**已确认：资料库及项目等记录中的资料链接只保存指针和链接。普通本地文档的一键唤起是第一版必做项，用户接受安装本机配套工具。**

服务器保存资料名称、地址、分类、用途、备注、关联和必要的归属信息。文件正文由用户在原位置自行保管；第一版不提供文件上传、云端附件托管或自动同步文件内容。

这项规则针对外部资料文件，应用内的客户、项目、订单、经验和复盘等业务记录仍按既有 PostgreSQL 规则保存。

| 地址类型 | 保存内容 | 第一版打开行为 |
|---|---|---|
| 网页链接 | `https://` 或 `http://` 地址 | 用户点击后在浏览器打开原网页，访问权限由原网站控制 |
| Obsidian 笔记 | 用于打开笔记的 Obsidian URI | 用户点击后请求系统唤起 Obsidian，打开对应库和笔记；要求当前设备已安装 Obsidian 并拥有目标笔记 |
| 普通本地文档 | 本地绝对路径或 `file://` 指针，保留 Mac／Windows 路径含义 | 用户点击后经本机配套工具调用系统默认关联应用，打开当前设备上的文件，如 Word、PDF 等 |

产品入口沿用资料库和记录详情中的添加资料、编辑链接及打开链接。支持多条链接；更正地址更新索引，删除或恢复资料索引遵循原业务规则，原文件保持在原位置。

本机配套工具的职责限于资料打开：

- 接收用户点击触发的本地文件指针，校验目标后使用系统文件打开能力；地址作为数据传递。
- 保留中文、空格和路径分隔符等真实含义，分别适配 Mac 与 Windows。
- 本地文件由当前设备处理，云端服务不代替用户电脑解析或访问本地文件。
- 文件不存在、地址已变化或缺少关联应用时，给出可理解的反馈；用户可更正地址，也可复制原地址自行定位。
- 未安装配套工具时，提供对应系统的安装说明和复制地址入口；复制地址是兜底能力，一键唤起仍属于验收要求。
- 本机工具不承担文件上传、云端文件预览或资料正文同步职责。

网页发送打开请求不等于文件已成功打开。页面使用“已发送打开请求”等准确反馈；实际结果需要可靠的本机反馈或由本机工具向用户展示。

浏览器不能作为跨平台、免安装打开任意本地文件的统一方案；远程网页的本地文件导航受浏览器安全规则限制。[Chromium 本地资源导航记录](https://issues.chromium.org/issues/40092668)

本机工具的具体形态、安装方式和打开结果回传方式由后续技术设计确定，可优先评估自定义协议启动器等轻量方案。浏览器文件选择控件的值不保证提供真实绝对路径，录入与技术适配不得把浏览器伪路径当作资料指针。[MDN 文件输入说明](https://developer.mozilla.org/en-US/docs/Web/HTML/Reference/Elements/input/file)

Obsidian 地址采用官方的笔记打开 URI，正确编码库名、文件名和路径。该资料入口用于打开既有笔记，不能把资料地址解释为创建、追加或修改笔记的指令。[Obsidian URI 文档](https://help.obsidian.md/Extending+Obsidian/Obsidian+URI)

### 9.1.2 资料打开验收

## 11. 编号、数据管理和 Agent

### 11.1 业务编号

来源：S1、S4、SC；网页版身份策略按数据库参照文档。

| 对象 | 原展示编号规则 |
|---|---|
| 客户 | `KHYYYYMMDDNNN` |
| 合作方 | `HZYYYYMMDDNNN` |
| 订单 | `ODYYYYMMDDNNN` |
| 收入 | `SRYYYYMMDDNNN` |
| 农活 | `BLYYYYMMDDNNN` |
| 资料 | `ZLYYYYMMDDNNN` |
| 经验 | `JYBXYYYYMMDDNNN` |
| 产品 | `CPBXYYYYMMDDNNN` |
| 项目 | `XM`＋五位区域内序号＋区域标签 |
| 周／月／季复盘 | `WeekRYYYYMMDD`／`MonthRYYYYMMDD`／`QuarterRYYYYMMDD` |

- 日期型编号取北京时间创建日期，三位当日序号从 001 开始，各实体独立计数；所有区域农活共用该用户适用范围内的 BL 序列。

- 复盘编号日期取复盘日期，无日序号；经验业务日期可编辑，不改变创建时生成的编号。
- 编号生成后固定，删除不复用，重启保持序列；改区域不改已有编号。
- 同次重试返回同一记录。容量溢出明确报错，不回绕生成重复编号。
- 原 App 以业务编号直接作为主键；网页版采用全局内部 ID 与展示编号分离，编号在所属经营簿或账号范围内唯一。
- 已确认沿用原业务编号格式，保留区域标签及 JYBX、CPBX 等前缀；去游戏化调整作用于界面文案。

### 11.2 数据一致性

- 统一数据源，记录及关联持久保存，页面刷新或服务重启后仍存在。
- 软删除保留关联、历史数据及实际收入，恢复沿用 ID。
- 更新、删除、恢复及完成动作检查版本；冲突返回最新记录，保留草稿，禁止静默覆盖。
- 新增、收入登记、沟通和日志追加支持请求去重，重试不重复记录。
- 数据结构采用版本化迁移，升级保护旧数据；虚构测试数据与正式数据分离。
- 网页个人版的数据归属、账号隔离、个人内容和后续团队权限以数据库参照文档为准。

### 11.3 Agent 读写能力

- 健康检查、业务汇总，各主实体列表／详情／新增／局部更新／删除／恢复。
- 沟通读取及追加、项目日志读取及追加、农活完成及取消完成、历史已完成事项查询。
- 搜索、筛选、排序、分页及字段含义与界面一致，统一业务校验和金额规则。
- 原列表分页默认 50、上限 200，排序字段有白名单；日志原返回完整数组，作为现有契约参考。
- 明确认证、校验、未找到、版本冲突、重复复盘、恢复写入暂停及服务异常，不暴露凭据。
- 是否接单、放弃、修改经营决定或删除，由用户决定，Agent 依据明确指令执行。
- 网页版用本人授权访问替代本机共享凭据，Agent 不直接连接数据库；授权方案遵循数据库参照文档。

## 12. 桌面能力的网页承接

此节保留原版功能目的，并明确网页运行方式需要适配，不把平台差异当成已实现能力。

| 原能力 | 原规则 | 网页承接方向／待明确项 |
|---|---|---|
| 运行与启动 | Mac 登录后台启动、单实例、菜单栏唤起 | 主应用由服务端运行、浏览器访问；资料打开的本机配套工具按第 9.1.1 节提供安装与唤起能力 |
| 关闭与退出 | 关闭窗口后台及 Agent 继续运行，主动退出停止 App | 浏览器关闭不停止云端服务；账号退出结束用户登录访问，不停止整个服务 |
| 首次使用 | 空白经营数据，真实空状态及新增入口 | 每位新用户的个人经营数据为空，并有对应空状态入口 |
| 资料打开 | 网页、本地文件、Obsidian 链接，多链接保存 | 只保存指针与索引；网页跳转原地址，Obsidian 通过笔记打开 URI 唤起，普通本地文档由用户已接受的本机配套工具一键打开；具体形态待技术设计，详见第 9.1.1 节 |
| 自动备份 | 每日一致性备份，原日备份保留最近 7 个日期 | 云端配置一致性备份、升级前保护及恢复验证；实际策略在部署方案中明确 |
| 手动备份及恢复 | 立即备份、选择备份恢复；恢复前确认、校验、备份当前数据、暂停写入，失败保护原数据 | 本人下载经营数据与私有内容备份；恢复回滚到备份时点，先保存当前快照并再次确认。包括资料指针，不含外部文件、密码或 Agent 密钥；只恢复本人业务数据，禁止覆盖平台整库 |
| 恢复后状态 | 刷新服务和窗口，使过期写入失效，凭据轮换 | 刷新用户数据视图，使恢复前过期请求不能覆盖恢复结果；授权处理结合网页登录及 Agent 方案 |

Next.js、PostgreSQL 的迁移和部署属于承接方式，不增加新的业务模块。原 App 业务数据导入并未在本轮单独提出，不能自动读取正式数据库或迁移真实记录。

## 13. 用户登录与账号密码管理

来源：本轮用户明确新增。

已确认：用户名＋密码、自助注册、人工找回。

- 用户自行注册；服务端统一规范化、校验并检查用户名唯一，密码以安全哈希保存。用户名作为登录标识，第一版不增加改名功能。
- 注册时原子创建账号、个人经营簿和唯一所有者关系，初始经营数据为空。
- 账号管理的最小实现为查看用户名、修改密码和退出登录；修改密码验证原密码。
- 人工找回通过运营者核验身份后受控重置密码；提供明确的联系说明及受控维护工具或命令，记录操作且使旧登录凭据失效。不仅提供一个没有实际处理流程的提示。
- 人工核验不能只凭知道用户名就重置；不自动增加邮箱、短信、第三方登录或用户运营后台。正式开放注册前配置真实找回联系方式与核验流程，由运营者落实。
- 登录身份与本人业务、私有内容及 Agent 授权对应。退出结束本人网页登录访问；人工密码重置须使该账号旧会话及旧 Agent 凭据失效。

用户名字符与长度规则、哈希组件、会话实现和人工维护工具形态交由技术 Agent 在既有认证架构中设计并记录，不构成新增产品模块。
