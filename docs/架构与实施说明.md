## 产品简报

```yaml
product:
  name: 光域空间
  one_liner: 面向 OPC 的个人经营管理工具，让用户和经授权的 Agent 围绕同一份经营记录协作。
  target_users: [中国大陆 OPC, 一人公司, 独立创业者, 个人经营者]
  core_user_stories:
    - 注册账号后从空白经营簿开始管理客户、合作方和项目。
    - 组织任务、交付、订单和实际收入，并查看统一经营汇总。
    - 索引外部资料，在当前设备打开网页、Obsidian 笔记或本地文件。
    - 沉淀经验、产品和周/月/季复盘。
    - 向外部 Agent 签发可撤销、可设范围和到期时间的本人数据凭据。
    - 下载本人数据备份，并在确认后安全回滚。
  business_model: none
  ai_capabilities: [授权外部 Agent 通过业务 API 读写本人经营数据]
  target_regions: [中国大陆]
  required_services: [Next.js Web, PostgreSQL 16, Redis]
  optional_external_providers: []
```

## 领域决策

| 领域 | 决策 | 一期实现 |
|---|---|---|
| 用户与认证 | `configure` | Auth.js Credentials 用户名＋密码、自助注册、查看账号、验证原密码改密、退出和受控人工重置；不伪造邮箱，不启用 OAuth、邮件或第三方登录。用户名不可自行修改。 |
| 经营簿与权限 | `design_needed` | 每人注册时原子创建个人经营簿及唯一所有者成员关系；预留成员模块权限及项目成员关系，不开放团队入口。服务端从会话身份取得用户和经营簿，不信任请求中的归属 ID。 |
| 平台计费 | `not_needed` | 一期无套餐、订阅、积分、支付、收费和平台商品。框架支付代码保留且运行关闭；客户订单、实际收入和产品资产采用独立模型。 |
| AI 模型与生成 | `later` | 不配置供应商密钥，不启用 Chat、生成和模型计费。只提供本人授权的业务 Agent HTTP API，不提供模型或数据库凭据。 |
| 经营业务 | `design_needed` | 一期实现客户、合作方、项目、任务、订单、收入、资料、经验、产品、复盘、沟通和项目日志。网页和 Agent 使用同一业务服务。 |
| 个人内容 | `design_needed` | 经验、复盘、学习提升项目/任务/日志/资料按 `user_id` 私有；不通过经营簿成员关系共享。 |
| 运营与增长 | `not_needed` | 关闭分析埋点、广告、营销触达、邮件运营、联盟和转化通知；重要业务变更写入本地审计记录，不向外部发送副作用。 |
| 外部资料 | `configure` | 只保存索引与指针；网页和 Obsidian 使用原地址；本地文件由最小 Mac/Windows 协议处理器通过系统默认应用打开。禁用框架对象存储和文件上传。 |
| 个人备份 | `design_needed` | 导出版本化本人业务快照；恢复前校验并保存一致性快照，确认后在本人范围事务性恢复；保留 ID、编号高水位和审计记录。 |
| 运行与安全 | `configure` | Next.js App Router、Prisma、PostgreSQL、必要 Redis，`SERVICE_MODE=web`。登录/注册和 Agent 写接口限流；生产使用安全 Cookie/HTTPS；日志不含密码、原始凭据或业务正文。 |

## 数据与服务边界

### 主要实体

- 账号与扩展：框架 `User` 增加规范化唯一用户名、口令版本；新增 `Workspace`、`WorkspaceMember`、`ProjectMember`。
- 经营簿记录：`Customer`、`Partner`、`Project`、`Task`、`Order`、`Income`、`Resource`、`Product` 及关联表。经营范围内均带服务端确定的 `workspace_id`。
- 个人私有记录：`Experience`、`Review` 及学习提升项目和子记录带 `owner_user_id`；只能由所属用户读取。
- 附属和控制数据：`Communication`、`ProjectLog`、`MaterialLink`、`IdSequence`、`RequestDedup`、`AuditLog`、`AgentCredential`。
- 订单与收入使用人民币整数分；订单金额可空，收入金额必须为正。金额汇总在共享业务服务实时计算，不另存可漂移的缓存值。
- 所有主记录保留稳定内部 ID、业务编号、版本、创建/更新时间和软删除时间。写入通过版本条件更新；关系两端在同一合法经营簿内校验。

### 模块和 API

- 产品业务实现为 `src/modules/guangyu-space/`，校验器与服务集中管理业务规则；网页和 Agent 都使用 Next Route Handlers，并调用同一服务层。本期未挂载框架 tRPC 路由。
- 外部契约版本前缀为 `/api/agent/v1`。包括健康、汇总、列表/详情/新增/局部更新/软删除/恢复、沟通和项目日志追加、任务完成/取消完成及完成历史。列表默认 50、上限 200，排序字段白名单化。
- Agent 凭据只显示一次，数据库只保存不可逆摘要、授权范围、过期时间、撤销和口令版本；请求每次重新验证账号状态及凭据状态。写请求要求幂等键和记录版本。
- 业务服务在数据库事务内写数据、编号、幂等响应和审计记录。收入汇总始终根据有效收入及所属订单重新计算。
- 本期不开启模板 Chat、平台订阅/支付、积分、供应商、营销、广告、云附件、Webhook、独立 Hono API、Worker 或移动端入口。保留源码、文档和许可；未启用的 App Router 页面与 API 源文件以 `.disabled` 后缀保留，不进入 Next 路由表。

### 一期完整范围

实施范围以功能整合文档为准，包含七组导航及全部已确认字段、选项、过滤、排序、分页、关联和状态：经营总览；客户/合作方；订单/收入流水；五类项目和学习排期；任务及历史；资料库；经验、产品和周/月/季复盘。详情抽屉、沟通/日志弹窗、草稿保护、资料打开、账号管理、Agent 授权和个人备份恢复均属于验收范围。

明确不启用：团队邀请与共享、成员授权 UI、实时协作、收费与积分、内置 AI、模型供应商、营销、广告、邮件触达、云附件和移动应用。

## 体验与交付路径

- 第一条演示路径：注册两个独立账号 → 各自录入客户和项目/任务 → 录入订单和收入 → 查看首页汇总 → 为第一个账号签发 Agent 凭据并执行一次新增或更新 → 确认另一账号不可见 → 下载并恢复该账号备份。
- 界面按《产品设计文档》使用正式 Logo、星云紫/青/玫瑰、雾灰背景、16px 业务表单与阅读文字；桌面详情抽屉约占 60%，小屏抽屉全宽。
- 生产/国内云仅准备部署配置、迁移、反向代理 HTTPS、持久化、日备份和恢复说明。本任务不创建云资源、不部署或上线。

## 实施决策记录

- 已确认的 MVP 范围直接由需求文件授权，不按 Harness 模板将 MVP 缩成假数据或删去既有功能，也不重复询问品牌、收费、范围或 Agent 方向。
- Harness 默认列表 20 条与本项目已确认的 50 条冲突，采用本项目 50/200 契约。
- 模板邮箱白名单登录与本项目用户名登录冲突，使用独立的真实用户名列；`email` 保持可空，不将用户名伪装成邮箱。
- 仅运行 Web；保留框架可选模块代码，但路由/API/服务器动作和外部副作用必须在运行边界关闭。
- 工作区此前没有 Git 元数据；如初始化 Git，仅创建本地开发分支，不创建远程，不 commit、merge、push 或上线。
- 原 App 目录只作只读核对；不连接、导入、复制或修改真实经营数据库。

### 数据模型与迁移

新增业务迁移：`prisma/migrations/20261015000100_guangyu_space_v0_1_0/migration.sql`。它扩展 `users` 的规范化用户名与口令版本字段，并创建以下 24 张经营簿表：

`ledger_workspaces`、`ledger_workspace_members`、`ledger_project_members`、`ledger_customers`、`ledger_partners`、`ledger_projects`、`ledger_project_customers`、`ledger_project_partners`、`ledger_tasks`、`ledger_orders`、`ledger_order_projects`、`ledger_incomes`、`ledger_resources`、`ledger_resource_projects`、`ledger_experiences`、`ledger_products`、`ledger_reviews`、`ledger_communications`、`ledger_project_logs`、`ledger_material_links`、`ledger_id_sequences`、`ledger_request_dedup`、`ledger_audit_logs`、`ledger_agent_credentials`。

迁移保留 Harness 原有历史，并补上 PostgreSQL 检查约束：个人学习项目必须是私有项目、任务最多关联一个客户或合作方、任务完成状态字段一致、订单/收入/产品金额不得为负、沟通对象与 `person_type` 一致；每本经营簿最多有一名 owner。Prisma Schema 与 Client 均已验证，真实临时 PostgreSQL 上已部署 60 条迁移，`prisma migrate status` 显示 schema up to date。没有执行模板种子数据。

数据库实际包含 88 张 public 表：80 张当前 Prisma 模型表、7 张 Harness 历史迁移留下但当前 schema 未建模的兼容表，以及 `_prisma_migrations`。一期运行实际使用 `users` 和 23 张 `ledger_*` 表；`ledger_workspace_members` 只保存每本个人经营簿唯一 owner 关系。`ledger_project_members` 与 Auth.js adapter 表 `accounts`、`sessions`、`verification_tokens` 保留为未来扩展结构，本期没有团队项目成员接口，也未启用 OAuth、邮件或数据库会话。

其余 52 张 Harness 模型表当前无光域空间业务入口，包含：`conversations`、`interactions`、`posts`、`affiliate_accounts`、`affiliate_ledger_entries`、`affiliate_earnings`、`affiliate_payout_requests`、`user_attributions`、`user_offers`、`user_stats`、`github_connections`、`github_repositories`、`agents`、`user_agents`、`image_assets`、`image_generation_tasks`、`image_generation_assets`、`activation_codes`、`projects`、`documents`、`project_quality_scores`、`products`、`product_prices`、`orders`、`payments`、`payment_webhook_logs`、`payment_transactions`、`membership_user_subscriptions`、`membership_user_subscription_cycles`、`membership_subscription_deliveries`、`membership_subscription_delivery_effects`、`membership_user_entitlements`、`product_subscription_plans`、`product_product_subscriptions`、`product_product_credits_packages`、`product_entitlements`、`product_plan_entitlements`、`product_product_one_time_entitlements`、`task_tasks`、`promo_codes`、`promo_code_redemptions`、`touch_scenes`、`touch_templates`、`touch_schedules`、`touch_records`、`user_notification_preferences`、`support_tickets`、`support_timeline`、`support_sync_cursors`、`feature_settings`、`service_connections`、`support_replies`。7 张未建模的历史表为 `billing_billing_accounts`、`billing_billing_freeze_records`、`billing_billing_records`、`video_assets`、`video_generation_outputs`、`video_generation_tasks`、`video_purchases`；它们没有被光域空间路由或服务调用。
